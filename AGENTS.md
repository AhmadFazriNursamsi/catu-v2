# AGENTS.md — Flutter Project Agent Configuration

## 🧠 Project Context
This is a Flutter app that connects to a Bun backend API (built by a teammate).
Codex should assist in generating UI pages, service layers, and state management logic
following clean architecture and Flutter best practices.

---

## 🎯 Primary Goals
- Generate and edit Flutter source code in `/lib/`
- Follow Material 3 (M3) design guidelines
- Use Dio for API networking
- Maintain folder-based modular structure:
- Implement state management using `Provider` or `Riverpod`
- Generate code that runs cleanly on Android emulator or web

---

## 🧩 Rules for Code Generation

### 1. UI / Screens
- Use `Scaffold`, `AppBar`, and Material components.
- Always wrap inputs inside `SingleChildScrollView` for safe scrolling.
- Reuse reusable widgets in `lib/widgets/`.
- Use `SizedBox` for spacing, not hard-coded padding.
- For colors, use `Theme.of(context)` instead of fixed hex values.

### 2. Networking
- Use the `dio` package.
- Store all HTTP calls in `lib/services/`.
- Base URL should be configurable in one place (e.g. `config.dart`).
- Handle errors using `try/catch` and return safe responses.

### 3. Models
- Generate models with `fromJson` and `toJson`.
- Use `required` named parameters.
- Follow Dart naming convention (camelCase).

### 4. State Management
- Use `ChangeNotifier` or `Riverpod` for state.
- Avoid logic directly in Widgets.
- Separate UI and business logic clearly.
